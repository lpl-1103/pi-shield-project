**期間**：2026-07-16 — 2026-07-21

## 本週摘要

從樹莓派 3 的鍵盤控制原型開始，一路擴充到樹莓派 4 上跑的完整 LINE 點歌機器人：點歌排隊、原聲/伴奏切換、同步歌詞、熱門電台、歌手推薦、播放紀錄，前端從陽春介面重做成有質感的深色玻璃風格。這週後半段接上本機 AI（openclaw + Bionic 本地模型）讓機器人聽得懂口語，加了語音點歌，也做出接電視用的大螢幕歌詞牆。專案已公開發布在 `github.com/lpl-1103/pi-shield-project`，每個功能都在真實硬體上驗證過才算完成，不是紙上談兵。

## 本週完成項目

### 核心點歌系統

- **KTV 風格點歌佇列**：排隊、切歌、頂歌、刪除、原聲/伴奏即時切換、同步歌詞（lrclib.net）、網頁面板即時輪詢更新。
- **熱門電台 + 歌手推薦 + @ 提及點歌**：三個分類（K-pop／中文流行／英文流行）自動連播；「推薦 歌手」列出前 5 首熱門歌回數字直接點；「@任何稱呼 歌名」比「點歌」更口語。
- **已播歌曲紀錄**：記錄最近播過的歌，網頁可以直接點擊重播確切影片；推薦與電台選歌都會自動避開最近播過的。

### 本機 AI：自然語言 + 語音

- **口語理解（openclaw + Bionic 本地模型）**：聽不懂固定指令格式時，交給 Mac 上的本地模型（qwen3-8b）翻譯成機器人指令再執行；刻意排除硬體控制指令、失敗一律安全退回「不認識的指令」。
- **語音點歌**：Mac 上另外架的本機 Whisper 服務（mlx-whisper，不經雲端）把 LINE 語音訊息轉文字，回覆會先附上聽到的內容再接處理結果。
- **大螢幕歌詞牆（`/display`）**：接電視/顯示器用的深色超大字歌詞頁面。樹莓派本身是無圖形介面的 Lite 系統，另外裝了最小化 X + Chromium kiosk，開機自動登入、自動全螢幕顯示。

### 維運與可靠性

- **全套服務自動啟動**：樹莓派端 systemd 管理 LINE 機器人 + ngrok；Mac 端 launchd 管理 openclaw gateway、Bionic 伺服器、Whisper 服務——重開機/當機都不用手動介入，實際重開機驗證過。
- **開源發布**：專案公開在 GitHub，README 重新設計（banner、badge、架構圖），`HANDOFF.md` 完整記錄每個決策的來龍去脈，換電腦也能無縫接手。

## 本週修掉的真實 bug

1. **重開機後沒聲音——ALSA 音效卡編號不穩定**
   音效卡編號寫死成 `hw:1,0`，但每次開機卡號可能互換，導致聲音播到沒接喇叭的板子上，所有日誌看起來都正常。改成開機時動態偵測。

2. **播放「成功」但沒聲音——mpv 錯誤被靜音吞掉**
   `--really-quiet` + 輸出導到 `/dev/null`，mpv 真正播放失敗時完全查不到原因。改成留 log 檔案。

3. **推薦歌曲很快就重複**
   舊邏輯只比對 YouTube 影片 ID，同一首歌不同上傳版本比對不出來；已播紀錄又用固定 30 筆上限，熱門電台開著跑很快就把記憶「洗掉」。改成標題正規化比對 + 12 小時過期機制。

4. **點歌人有時候被誤判成「匿名」**
   LINE 個人資料查詢失敗時也會被永久快取成「匿名」，一次網路瞬斷就永久卡住。改成只快取成功結果。

5. **歌詞出現一堆 `<00:00.000>` 亂碼**
   部分歌曲的同步歌詞是逐字時間標記格式，行內標記從功能一開始做就沒被過濾掉，直到大螢幕字放大才被發現。

6. **大螢幕中文字/emoji 顯示成方框**
   樹莓派最小化安裝沒有任何中文或 emoji 字型，補裝 `fonts-noto-cjk` + `fonts-noto-color-emoji`。

## 下週目標

1. **驗證大螢幕 kiosk 模式的實際顯示效果**——目前每個設定檔都已就位並單獨測過，但整條「開機 → 自動登入 → 全螢幕顯示」的流程還沒有真人在螢幕前確認過。
2. **語音點歌端對端驗證**——本機 Whisper 轉文字本身已測過，但 LINE 語音訊息下載這一段沒辦法用假資料測試，需要傳一則真實語音訊息才能完整驗證。
3. **持續調整本地 NLU 翻譯品質**——目前 qwen3-8b 大約七成準確率，可以再嘗試 prompt 微調，或視 Mac 記憶體餘裕評估換更大的本地模型。
4. **評估其他創新方向**——先前討論過的幾個點子還沒開始：LED 燈光隨音樂節奏聯動、點歌排行榜/統計頁面、麥克風實體輸入效果器。
