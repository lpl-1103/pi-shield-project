# FRDM-MCXA153 開發週報

**期間：2026/07/17 – 2026/07/21**

## 本週完成項目

### 1. 評估 Embedder（商用 AI 韌體代理平台）— 結論：不適用

調查該產品的部署方式，發現雖然有個人免費帳號可註冊，但核心 CLI agent 被「evaluation license」鎖住，個人/學生身份無法取得授權，決定放棄，改用開源工具鏈自建開發環境。

### 2. 建立 Zephyr RTOS 開發環境（macOS）

從零裝好完整工具鏈：Homebrew 依賴、Python 3.12 虛擬環境、west、Zephyr SDK、workspace 初始化。過程中排除了 `qemu` 編譯失敗（改為跳過，不影響真實硬體燒錄）等問題。

### 3. 板子基本能力驗證

- 燒錄官方 `blinky` 範例確認工具鏈全通（FLASH 14.4% / RAM 16.1%）
- 盤點板載資源：RGB LED、3 顆按鍵、P3T1755 溫度感測器（I3C）、USB device、16-bit ADC、Arduino/mikroBUS/Pmod 擴充孔位

### 4. 開發 `rgb_demo` 應用

SW3 開關 LED、SW2 觸發連續色彩漸變（軟體 PWM）、每 2 秒讀取板載溫度感測器並印出。過程中抓出一個實際的 bug：初版用 `k_busy_wait` 忙等做 PWM，佔滿 CPU 導致按鍵中斷進不來，改成計時器中斷驅動後修復，並在真實硬體上驗證溫度讀值與按鍵反應皆正常。

### 5. 動態程式載入（LLEXT）可行性驗證

研究並確認 Zephyr 的 **LLEXT** 子系統可在不重新燒錄的情況下，把小程式即時載入 RAM 執行，且 ARM Cortex-M 有官方支援。裁剪出最小可用設定（FLASH 49% / RAM 87%），實際編譯一個測試模組、透過序列埠 `load_hex` + `call_fn` 動態載入並執行成功，過程中排除兩個真實問題：符號匯出設定遺漏、雙模組同時常駐導致記憶體不足。

### 6. 樹莓派端部署腳本

寫出 `deploy.py`（Python + pyserial），自動化「編譯 → 轉十六進位 → 序列埠載入 → 執行 → 回報結果」全流程，並在本機模擬樹莓派角色實測跑通，修正了開埠觸發重開機的等待時機、以及重複部署時的自動卸載邏輯。

### 7. 專案歸檔

所有程式碼（`rgb_demo`、`llext_min`、測試擴充模組、`deploy.py`）已存入現有本機專案 repo 的 `frdm_mcxa153/` 資料夾（尚未 commit）。

## 下週目標

1. **在真正的樹莓派 4 上實測 `deploy.py`** —— 本週只在 Mac 上模擬過，樹莓派的序列埠路徑（`/dev/ttyACM0`）、交叉編譯工具鏈安裝都還沒驗證
2. **重新分配 LLEXT 的 RAM 預算** —— 目前 87% 太緊繃，需要依實際會載入的擴充模組大小，決定要縮小 `LLEXT_SHELL_MAX_SIZE`，或改用二進位傳輸取代十六進位（省一半空間）
3. **決定整合方向**：`rgb_demo`（LED/按鍵/感測器）與 `llext_min`（動態載入）目前是兩個獨立韌體，要不要合併成一份基礎韌體，讓樹莓派動態載入的模組也能操作 LED/讀感測器
